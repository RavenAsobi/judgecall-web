## 一、项目目标

把离线版 `demo.html`（TCG 赛事工具 Lynx）改造为 **多人在线联机版**，最终部署到服务器。
- **功能与 UI 完全不变**，仅把 localStorage 模拟替换为真实后端 + WebSocket 实时同步。
- 网页拓展插件 `dist/` 已可用，暂不修改，仅分析对接协议。

## 二、已确认技术决策（2026-07-25）

| 决策点 | 结论 |
|---|---|
| 数据存储 | **SQLite 单文件**（零配置、随项目部署、备份即拷文件） |
| 实时同步 | **WebSocket**（长连接广播，demo 已预留通道） |
| 部署节奏 | **先本地跑通联调，再出部署文档上云** |
| 前端形态 | **拆成工程化项目**（Vite + 原生 JS 模块，需核对 UI 一致性） |

## 三、权限体系（来自 权限等级.txt）

| 角色 | 密码 | 权限 |
|---|---|---|
| 原初权限 super | 由 `server/.env` 的 bcrypt 哈希配置（明文不写入项目文档） | 最高权限：免密进赛、删赛、看所有激活密码、关闭密码、发放任意有效期普通密码、创建比赛生成单场密码 |
| 普通权限 admin2 | `666666`（P001，无限期）等 | 免密进赛、创建比赛生成单场密码、发放固定 1 个月有效期的次级密码、不能删已开始比赛 |
| 次级权限 admin3 | 普通用户发放 | 可创建比赛、不能删任何比赛、不能发放密码 |
| 比赛权限 event | 单场 6 位密码 | 仅修改对应一场比赛，其他比赛视作游客 |
| 游客 guest | 比赛密码 | 只能调整桌子方块状态 |

编号体系：原初=001（不显示）、普通=P001+、次级=C001+、单场=D001+

## 四、服务器需保存的数据（来自 那些数据要保存在服务器.txt）

1. 所有权限密码
2. 比赛列表的所有比赛
3. 每场比赛内的设置、桌子方块状态、倒计时等
4. 每个权限密码在顶部保存的比赛入口（pins）
5. 用户名进入记录：3 天内免密，首次进入计时 3 天，之后每次进入若有效期 <24h 则刷新至 24h，过期清空缓存
