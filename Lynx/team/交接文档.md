## 三、后端 `server/`（端口 3000）

技术：Express（REST）+ ws（WebSocket，路径 `/ws`）+ better-sqlite3（单文件 `lynx.db`，WAL 模式，外键开启）。

| 文件 | 行数 | 职责 |
|---|---|---|
| `index.js` | 95 | 入口。挂 Express + HTTP + WS；CORS；**启动时统一清理**（见下）；路由挂载；**托管 web/dist 静态文件 + SPA 兜底**（7-26 下午加，单端口模式，供穿透/生产用） |
| `db.js` | 455 | 数据访问层。建表、ensureColumn 旧库兼容、所有 SQL 语句、各业务函数 |
| `auth.js` | 122 | 权限鉴定。resolveCredential（密码→角色）、中间件（attachAuth/requirePrivileged/requireEventPriv/requireSuper 等）、eventCodeValid（单场码 7 天过期） |
| `ws.js` | ~300 | WebSocket。房间管理、join/leave、tables:patch、timer:cmd、**成绩回报 report/report:ack/report:clear/report:roundclear**、广播（snapshot/tables/timer/tournament/deleted/lobby/reports/report:new/reports:roundclear/error） |
| `routes/auth.js` | 76 | `/api/auth/login`、`/api/tournaments/:id/verify`、`/api/tournaments/:id/enter`（记录进入）、`/api/my-entries`（查我的进入记录） |
| `routes/tournaments.js` | ~210 | 比赛 CRUD（GET/POST/PATCH/DELETE），PATCH 里含规则 4（改密码清免密）；**GET /:id/reports 回报历史**（requireEventPriv，注册在 /:id 之前） |
| `routes/grants.js` | 92 | 权限密码的发放/查询/作废/停用 |
| `routes/pins.js` | 28 | 顶部保留入口（GET/PUT） |

### 数据库 8 张表（db.js 顶部建表）
1. **grants** — 普通权限密码（只保留 level=2，P 前缀编号 P001+；super 密码使用 `server/.env` 中的 bcrypt 哈希，**不入库、不硬编码**）
2. **tournaments** — 比赛（含 eventCode/eventNum 单场码、lastAccessAt/lastOpAt/endedAt 三个生命周期时间戳）
3. **tables** — 桌子方块（含 greenManual/greenAt 染绿计时）
4. **timers** — 轮计时器（服务器权威：configured/remaining/running/updatedAt）
5. **pins** — 顶部保留入口（按 credential 关联，跟密码走不跟设备）
6. **user_cache** — 用户名免密 + 最近进入记录（3 天滑动续期；兼作"最近进入排序"的数据源）
7. **reports** — 成绩回报（7-26 加；round/kind/body/reporterName/reporterCredential/text/dup/conflict/grp/roundCleared/createdAt；历史永久保留。相同/不同按轮数+桌号判定：成绩同分→dup 不入框、不同分→新旧全标红同组；drop 同玩家→新标红旧入组不标红）
8. **report_acks** — 回报确认（reportId+viewerCredential，每个权限用户独立确认；确认=只从自己消息框隐藏）

所有从表都设了 `ON DELETE CASCADE`，删比赛会连带清干净。

### 后台的定时/启动任务（index.js + db.js）
- **启动时**（每次重启跑一次）：`purgeExpiredGrants()`（清失效超 90 天的密码）+ `startupPurgeTournaments()`（判比赛结束 + 删超 90 天的已结束比赛）。用户说"服务器每周一重启一次，每次启动检查一次"，自动重启脚本（cron/PM2）**留待部署时配**。
- **每天 00:00**：`reclaimStaleTimers()`（规则 6）——回收超 24h 的计时痕迹：①轮计时器重置回满时长未启动 ②染绿只清 greenAt（颜色不变）③**顺带清空这些比赛在所有权限用户的 pins**。有清 pins 时 broadcastLobby 让在线用户顶端实时刷新。

## 五、权限系统（重点，改过好几轮）

**4 级**（权限等级.txt 为准）：

| 角色 | 命名 | 能做什么 |
|---|---|---|
| `super` | 原初 | 全部权限；能删任何比赛；能发自定义有效期普通密码和单场密码；密码由环境变量中的 bcrypt 哈希校验 |
| `putong` | 普通 | 能建比赛（勾选生成单场码）；**不能删进行中比赛**；**不能发普通密码**（只能发单场码）；看不到"发放权限"Tab |
| `event` | 比赛 | **只在特定某场**有 putong 级操作权；**其他场视作游客**；**不能删任何比赛（含自己那场）** |
| `judge` | 游客 | 输比赛密码进入，**只能调桌子方块状态** |

**关键实现点**：
- 后端**每条通道都要鉴权**：REST 用中间件（requirePrivileged/requireEventPriv），**WS 也要**（tables:patch/timer:cmd/report 系列里有 isEventPriv + eventCanAccess 校验）。曾踩过"REST 有鉴权但 WS tables:patch 没鉴权"的洞。
- **回报面板的"管理权"判定**与操作按钮同规则（canManage），但"是否收到某条回报"按**权限密码**区分：同一密码=同一身份，自己的操作不进自己框（历史里能查到）。
- 前端**按钮显隐**用 `canManage(t)`（state.js）——super/putong 任何场 true；event 仅自己场 true；judge false。**不要再用裸数组 `['super','putong','event'].includes(role)` 一刀切**（那样 event 在别场也会看到操作按钮，是个已修复的 bug）。
- "删除比赛"按钮（index.html `ts-delete-btn`）按 `canDelete(t)` 控制，event/judge 永不显示。
- 单场密码 = 比赛日期 + 7 天失效（`待定` 永不过期），auth.js `eventCodeValid`。
