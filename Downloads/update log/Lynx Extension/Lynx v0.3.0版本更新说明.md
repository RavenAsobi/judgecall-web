# Lynx v0.3.0版本更新说明

本次更新重点优化了 **Melee** 与 **EventLink** 的赛事数据识别能力，进一步提高比分、平局及退赛状态的提取准确性，同时改进了新一轮比赛的识别逻辑，降低部分桌次导入时误清空已有数据的风险。

## ✨ 新功能

### 更准确的具体比分识别

Lynx 现在可以从 **Melee** 和 **EventLink** 中直接提取实际比赛比分，包括：

- 牌手 1 胜场数

- 牌手 2 胜场数

- 平局局数

因此，诸如 **1–0、3–2、0–0–3** 等实际比赛结果将能够被正确保留，不再统一按照默认的 BO3 比分显示。

### 全新的「新一轮」识别机制

优化赛事轮次切换逻辑。

此前，当仅导入经过筛选的部分桌次，且这些桌次尚无比赛结果时，系统可能误认为进入了新一轮，并清空其他桌子的已有状态。

v0.3.0 引入新的轮次识别机制，只有在 Lynx 明确认定导入内容属于完整新一轮时，才会触发桌面状态重置和轮次更新。

部分桌次导入现在只会更新对应桌子，不会影响其他桌次。

### 新增桌面重置功能

新增 **重置** 按钮，可手动清空所有桌子的比赛状态，包括比分、补时、颜色及注释等信息。

执行前会进行二次确认，避免误操作。

## 🛠️ 问题修复

### Melee

- 修复 **0–0–3、1–1–0 等平局结果无法识别**的问题。

- 修复实际比分丢失、被错误显示为默认 **2–0** 的问题。

- 修复由 **牌手 2 获胜时比分顺序颠倒**的问题。

- 修复部分异常数据解析失败后被错误识别为 **0 分**的问题。

- 修复无法匹配获胜牌手姓名时仍写入比分的问题。

- 增加对 **中英文 Melee 后台**的兼容，可识别 `胜 / won`、`平局 / Draw`、`未报告 / Not reported` 等状态。

- 修复双方均退出比赛时 **“所有牌手缺席”状态无法识别**的问题，并增强中英文退赛状态兼容。

### EventLink

- 修复 **0–0–3 平局无法正确识别**的问题。

- 修复实际比赛比分无法提取、前端只能显示默认比分的问题。

- 优化含 Draw 数据时的比分读取逻辑。

## 🔄 兼容性

新增的具体比分数据保持向后兼容：

- 新版 Lynx 可以向兼容前端提供更加准确的实际比分；

- 旧版数据中没有具体比分时，系统仍可按照原有逻辑正常处理；

- GEM 等 BO1 来源继续使用现有结果格式，不受本次更新影响。
